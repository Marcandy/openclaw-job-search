# OpenClaw Job-Search Automation — Architecture

**Written 2026-09-29.** Maps every component of the campaign system: what it does,
whether it is custom-built or borrowed, and which file to open.

## Pipeline overview

```
DISCOVER          FILTER             AUTHORIZE            SUBMIT            AUDIT
discover.py  ->   role-filter.mjs -> authorize-pool.mjs -> browser agent -> check-ledger.mjs
(JobSpy wrap)     validate-pool.mjs  verify-authorization  (Kimi/InAppBrowser)  dashboard :4545
     |                 |                  |                    |                 |
 leads-*.json    candidates-*.json   state JSON +        receipt PNGs +      openclaw-
                                     poolHash (SHA-256)   ledger rows        application-log.csv
```

Daily trigger: OpenClaw cron job `cad8a8a0-22be-4990-9781-f08eb27365a8`, 12:30 PM ET,
regenerated by `sync-cron.ps1`.

## Components

### 1. Rules engine — the custom core (no open-source equivalent)

| File | Role |
|---|---|
| `campaign.config.json` | Single source of truth (923 lines). Per-city quotas and location aliases with same-name-city exclusions (Newark CA/DE/OH vs NJ; San José, Costa Rica; Atlanta TX/MI), banned title tokens (senior/staff/principal/lead…), experience gate (min-years > 5 rejected), role-relevance gate (title must contain an engineering token), skill-mismatch gate (rejects hard requirements in C++/.NET/Ruby/Flutter…), eligibility gate (no current-student, internship, or hard master's/PhD requirements), compensation floor ($90k min / $120k desired), company-profile filter (headcount bands, ~250-name household deny list, dated thriving signals with source URLs), source filter (official ATS URLs only, posting-age rules), ATS conversion tiers measured from the ledger, and the state machine (idle → researching → awaiting_authorization → authorized → submitting → quota_complete/exhausted). |
| `lib/role-filter.mjs` | Pure predicate logic implementing every gate. No network, no applicant data — testable in isolation. |
| `validate-pool.mjs` | CLI gate: dedupes candidates against the CSV ledger and assembles the daily pool. A research run cannot present a pool without clearing it. |
| `test/role-filter.test.mjs` | 77 tests — every gate, every banned title, every ">5 years" phrasing. |

Why code instead of prose: before 2026-08-16 the rules were Markdown an LLM read;
Senior/Lead/Principal roles kept reaching the pool. *"A rule that only exists as
prose is a suggestion."*

### 2. Authorization integrity — custom

| File | Role |
|---|---|
| `tools/authorize-pool.mjs` | The only supported path to status `authorized`. Records `authorizedAt`, `authorizedBy`, `poolHash`, `exactUrls`. |
| `tools/verify-authorization.mjs` | Pre-submission check: recomputes the SHA-256 over the sorted URL list and refuses to run if it differs — no process can swap a destination into an approved batch. |
| `test/authorization-flow.test.mjs` | 11 tests: authorize → verify → tamper lifecycle. |

### 3. Discovery — borrowed (open source)

| File | Role |
|---|---|
| `discovery/discover.py` | Wraps [JobSpy](https://github.com/speedyapply/JobSpy); queries Indeed, LinkedIn, ZipRecruiter, Google Jobs with real location + radius. Output: `leads-YYYY-MM-DD.json`. |
| `tools/leads-to-candidates.mjs` | Triage: runs leads through the cheap deterministic gates before expensive LLM research. |

### 4. Submission — commodity layer (currently Kimi + InAppBrowser)

An agent drives a real browser through Ashby / Greenhouse / Lever / Gem forms using
the approved facts in `openclaw-applicant-brief.txt`, captures a visible receipt
(`openclaw-runtime-logs/receipt-*.png`), and logs the row. Swappable — see
`SWAPPABLE_PARTS.md`.

### 5. Ledger & audit — custom

| File | Role |
|---|---|
| `../openclaw-application-log.csv` | 181-row append-only ledger: every discovered/submitted/blocked outcome. The empirical basis for ATS conversion tiers and company-level blocker memory. |
| `tools/append-ledger.mjs` | Append a row (added 2026-09-29). |
| `tools/check-ledger.mjs` | Integrity audit: row shape, timestamps, URLs, duplicate detection (added 2026-09-29; 125 tests). |
| `tools/list-blockers.mjs` | Companies whose form asks an unanswerable question — blocks them for ALL future roles. |
| `tools/verify-candidates.mjs` | Cross-checks recorded claims against the live posting. |
| `tools/fact-gaps.mjs` | Ranks missing applicant facts by how many applications they block. |
| `tools/check-city-matching.mjs` | Diagnoses location-alias false positives. |
| `tools/ats-stats.mjs` | Recomputes per-ATS conversion from the ledger. |

### 6. Surfaces

| File | Role |
|---|---|
| `dashboard/server.mjs` | Campaign dashboard on `127.0.0.1:4545` with a "Search again" button. Start: `powershell -ExecutionPolicy Bypass -File dashboard\start-dashboard.ps1`. |
| `../integrations/jobsync/` | JobSync service on `127.0.0.1:3737`. |
| `../OPENCLAW_AUTOMATED_JOB_SEARCH_HANDOFF.md` | Running handoff log; section 0 has the latest state. |
| `../openclaw-tri-city-state.json` | Current campaign state, pool, and authorization record. |

## Design principles

1. **Rules are executable, not prose.** Every hard filter is code with tests.
2. **Never invent a fact.** Missing applicant data blocks the application; it is
   never guessed. Unposted salary = uncertainty, not a number.
3. **Authorization is tamper-evident.** Pool hash binds approval to exact URLs.
4. **Outcomes feed back.** The ledger decides ATS tiers, blocker memory, and dedupe.
5. **Receipts or it didn't happen.** A submission counts only with a visible
   confirmation captured to `openclaw-runtime-logs/`.
